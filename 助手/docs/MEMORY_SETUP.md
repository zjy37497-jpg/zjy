# 搭搭长期记忆接入与部署

## 已完成与未完成
已在桌面“助手”项目接入：三个 Skill、模型工具调用循环、独立档案页面、按微信身份隔离的档案服务、确认后写入、版本冲突保护和幂等确认。未部署到云端，未真实连接模型、数据库或真机验收。

聊天默认走云函数，不再因为客户端 apiKey 非空而绕过档案服务。原本地基线和自定义固定回复保留。右上角更多新增“个人档案与长期记忆”。云服务失败时显示失败，不再悄悄用通用本地计划冒充个性化结果。

## 1. 确认环境
在云开发控制台找到实际环境 ID，填入 utils/cloudConfig.js 的 env。cloud1 可能只是环境名称，不要根据名称猜 ID。空值使用当前默认环境，正式部署建议明确填写。

chat 只允许通过本微信小程序的 wx.cloud.callFunction 调用。本实现逐请求读取 getWXContext 的 OPENID 和 APPID 并生成隔离键；不要为它开启 HTTP、Web 或混合来源调用。若未来需要这些入口，先增加独立、经过验证的身份适配，不能直接复用当前身份逻辑。

## 2. 创建数据库集合
创建 dada_profiles 集合，权限设为客户端不可读、不可写，仅云函数服务端访问。禁止设为所有人可读写。按控制台实际权限编辑器配置 read=false、write=false，并在测试账号上验证客户端直读直写被拒绝。

读取不会创建空档案；第一次明确确认开启记忆才创建设置记录。一个用户一份文档，最多50条资料。数据库故障不会被当作空档案。

## 3. 设置 chat 环境变量
- LLM_API_KEY：模型服务密钥，只放云函数环境变量。
- LLM_BASE_URL：兼容 Chat Completions 的 HTTPS 地址前缀；不填写则沿用原来的智谱地址。
- LLM_MODEL：必须支持 tools/function calling；不填写沿用原默认 glm-4-flash。请按实际账户支持情况选择，不保证所有模型可用。
- PROFILE_ENABLED：填 true 才开启档案后端入口；不设置则保持关闭。
- PROFILE_SIGNING_KEY：至少32字符的高熵随机密钥，用于签名确认令牌。建议本机执行下面命令生成，自己复制到控制台，不发到聊天，不写入客户端或仓库：

    node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

所有 chat 实例使用同一签名密钥，轮换会使尚未确认的提案失效。没有配置签名密钥时，档案入口明确报未配置，普通聊天仍可在模型正确配置后使用。

## 4. 部署云函数
在开发者工具中对 cloudfunctions/chat 执行“上传并部署：云端安装依赖”。设置云函数超时至少60秒；当前最多3次模型请求，每次有18秒上限，数据库操作也需要余量。客户端调用上限70秒。实际资源和超时限制以账户环境为准，遇到限制需降低轮数或分步调用。

部署包含 SKILL.md、assistant-rules.md、skills 目录、profile.js、tools.js、knowledge.js 和 knowledge.json，不能只上传 index.js。安装沿用项目 wx-server-sdk 依赖，无新增第三方依赖。

## 5. 使用和授权
1. 编译小程序，右上角更多→个人档案与长期记忆。
2. 确认开启功能。这只允许读取你已确认的档案，不授权静默保存。
3. 回到聊天，例如“请记住，我家里没有器械”。模型提出变更后，核对弹窗内容再确认。
4. 健康资料也必须逐条确认。不确认或取消不会保存待选事实；提案只返回给客户端，不预先写入数据库。
5. 档案页支持查看、更正、删除、关闭记忆、清空并关闭。关闭保留旧资料但不再读档生成建议；清空会删在线记录并关闭。
6. 备份和平台日志需要按实际云服务的保留策略配置；代码不能承诺云服务备份瞬间清除。发布前制定完整保留与清理政策。

安全机制：提案绑定用户、版本和10分钟有效期；确认时验签并用数据库事务提交。重复确认不重复新增；旧版本提案不能覆盖后来的更改。模型不能直接调用确认接口。确认是可信小程序界面的业务步骤，不是模型输出一句“用户同意”。

## 6. 知识库
cloudfunctions/chat/knowledge.json 当前为 []，因此不向模型开放检索工具，不虚构检索成功。

第一版是服务端文档片段的关键词检索，然后把实际片段交给模型回答；不是向量检索，也未连接外部知识平台。加入审核过的真实资料并重新部署后自动启用。格式示意，不要把下面占位内容直接当知识发布：

    [{
      "id": "唯一片段ID",
      "title": "真实资料标题",
      "text": "经审核的原文片段（最多12000字符，建议每段不超过4000字符）",
      "keywords": ["至少两个字符的主题词"],
      "source_url": null,
      "updated_at": null
    }]

匹配最多返回3段，知识查询每轮最多2次。无匹配明确返回 empty。不得把用户档案或私人聊天加入公共知识文件。后续可替换 knowledge.js 的检索实现，保留相同返回字段。

## 7. 发布前重要检查
utils/config.js 原有调试配置没有删除。即使 directDebug=false，客户端文件里的密钥仍可能被打包，发布前必须清空 apiKey；若曾上传或分享过含密钥的代码，应到服务商轮换密钥。不能只关闭调试开关就认为密钥已安全。

如需本地直连对照测试，utils/cloudConfig.js 的 directDebug 可设为 true，并使用原调试配置。该路径不具备这次的云端长期记忆，发布前必须恢复 false。不修改原基线回复内容。

本地计划页仍沿用原来的计划生成逻辑，本次档案个性化接入的是聊天链路，不代表计划页已经按健康档案自动生成康复安排。

## 验证
已完成修改文件的 JavaScript 语法检查；20项档案/知识基础模拟检查；模型读档续答、客户端伪造 knowledge 忽略、模型仅提案不落库、确认端点写入、未配置入口拒绝等模拟检查。另验证模型传入 user_id 被拒绝。

未完成：微信模拟器编译、真机、真实模型工具兼容性、真实数据库事务和权限、云部署、真实跨会话测试。模拟数据库不证明真实数据库权限和并发事务正确。

上线验收：两个微信测试账号互不可见；取消弹窗不写；重复确认不重复写；并发更改冲突；关记忆后不读旧档案；删除后旧确认不能恢复；重进同一账号读取已确认资料；RAG 空或故障不编造来源。
